# 地点候補と天気

タイトルは必須。天気用の地点は任意です。登録済みの景色も「編集」から地点を追加できます。

## 登録

1. URLとタイトルを入力します。
2. 常時表示される「天気の地点」に地名を入力すると、500ms後に候補を自動検索します。初期値はタイトルから推測します。
3. 都道府県・地点名・緯度経度を確認して候補を選びます。
4. 「景色を登録」または「変更を保存」で登録します。保存後も同じ画面に残り、続けて登録できます。「景色を見る」へ切り替えると全景色のタイトル・天気・気温を流します。

検索語はライブ・解像度などを取り除き、市区町村・短い地名へ最大5段階で検索します。検索APIの2文字検索は完全一致のため、「札幌」で空なら「札幌市」も探します。都道府県の指定は維持し、保存済みの「北海道 / 札幌市」形式も再検索できます。自然言語AIやYouTubeの位置情報取得は使っていません。複雑な施設名・同名地名に誤一致する場合もあるため自動確定しません。検索語は利用者が修正できます。候補は日本国内に限定しています。

地点名・緯度・経度は本人の `camera_submissions` に保存します。カメラそのものの精密な位置ではなく、選択した代表地点の天気です。「登録地点を外す」で3列とも解除できます。既存のタイトルは変更せず、座標も推測して登録していません。

## 天気

Open-Meteoの `current=temperature_2m,weather_code` を摂氏・日本時間で取得します。天気はモデルの予報値で、映像からの判定や現地観測の保証ではありません。情報帯の天気にカーソルを置くとデータの対象時刻が分かります。

- 同じ座標の取得を共有し、15分キャッシュします。最大100地点。
- 再生していない景色も含め、登録地点を座標で重複排除して15分ごとに更新します。
- 地点を切り替えた後に旧地点の応答で上書きしません。
- 未登録・取得中・取得失敗を区別します。失敗を0°Cや晴れとして表示しません。
- 天気の失敗で動画再生・自動切替を止めません。
- 通信タイムアウトは8秒。検索は画面離脱・編集キャンセル・別検索時に中断します。
- 共有中の天気リクエストは画面離脱で中断せず、取得結果の画面反映だけを止めます。

APIキー・外部SDK・位置情報のブラウザ権限は使いません。検索時の地名と、天気取得時の選択座標だけをOpen-Meteoへ送ります。ノートやSupabaseの認証情報は送りません。

## 検証

Node.js標準テストで検索語生成・都道府県維持・日本の候補だけの採用・不正座標除外・天気応答の検証・天気コード表示・並行取得共有・期限切れ・通信失敗からの再取得を確認します。

`tests/scenery-list.sql` は空タイトル・不完全な位置・範囲外座標の拒否、本人の位置保存/解除、非管理者拒否をトランザクション内で検証し、変更はロールバックします。

ローカルの疑似DBと実際のOpen-Meteo APIを使い、渋谷の候補選択・保存・天気表示・地点未登録動画への切替・390×844の表示を確認しています。本番データの座標は変更しません。

2026-11-06の修正では「札幌」入力で候補が空になる問題を再現し、市名を補う検索と検索状態の表示を追加しました。入力待ち・検索中は検索語付きで表示し、完了後は件数・時刻を表示します。ローカルの疑似DBと実APIを使い、既存動画の編集で「札幌」入力→候補選択→保存→天気反映、再検索の完了時刻更新を確認しています。テストで2文字の地名が空の場合の再検索を固定しました。
