# 動画の視聴と公開

## 視聴方法

管理画面（`/admin`）の各動画で次を選べます。

- **動画をプレビュー**: 管理画面内で再生。公開状態は変えません。
- **別画面で視聴**: `/watch/<YouTube動画ID>` を新しいタブで開きます。
- **トップに公開**: タイトルとYouTube動画情報だけを公開カタログへ追加します。
- **非公開に戻す**: 公開カタログから取り除きます。登録候補やメモは残ります。

トップページは公開カタログの新しい順に最大100件を表示し、動画の選択と前後移動ができます。新しく公開・非公開にした状態は、トップページを開き直すと反映されます。

単体視聴ページは、URLで指定した公開YouTube IDを再生するページです。登録候補の一覧・タイトル・メモはDBから取得しません。単体視聴URL自体を他の人へ共有することはできますが、それによって公開カタログへ追加されることはありません。

## プレーヤー

YouTube公式IFrame Player APIをスクリプトで読み込みます。APIキーや追加SDKは不要です。

- プライバシー強化モードの`youtube-nocookie.com`を使用。
- ミュートしてから再生開始。ブラウザが自動再生を止めた場合は、再生操作を案内。
- 音声・再生/一時停止・全画面表示はYouTube標準コントロールで操作。
- 動画変更・画面離脱時にプレーヤーを破棄。
- 動画削除・非公開・埋め込み禁止・再生元識別エラーを区別して案内し、再試行とYouTubeへのリンクを表示。
- `origin`と`strict-origin-when-cross-origin`を設定して再生元を識別。
- PCは16:9。スマホではYouTubeの最小サイズに合わせ、高さ200px以上を確保。

再生できることと、現在ライブ配信中であることは別です。ライブ状態を自動判定してLIVEバッジを出す処理は実装していません。所在地・座標・天気も推測せず、未登録/未取得として表示します。

## 公開データと権限

`camera_submissions`は引き続き管理者専用です。メモ・作成者などの権限は緩和しません。

新しい`camera_videos`には、`id`・`youtube_video_id`・`title`・`published_at`だけを保存します。匿名利用者にはSELECTのみ、書き込みはRLSで確認済みの管理者に限定します。`publish_camera_submission`はSECURITY INVOKERで、管理者権限を確認し、候補のID・動画ID・タイトルだけをコピーします。

既存の登録候補5件を自動で公開する処理は実行していません。管理画面で対象を選んで公開してください。

## 検証（2026-11-05）

- 登録済み5件（観音沼森林公園・札幌すすきの・淡路島モンキーセンター・新宿歌舞伎町・渋谷スクランブル交差点）で実際のIFrame APIの再生中状態を確認。
- 390px幅で再生中を維持し、横はみ出しがないことを確認。
- 管理者の公開・非公開、匿名の公開情報SELECT、非管理者の公開拒否をDBで確認。検証はロールバックし、公開状態は変更していません。
- 匿名RESTで候補のメモを取得できないことを確認。
- ESLint・TypeScript・Node.js標準テスト23件・本番ビルドが成功。

Supabase Advisorでは、非公開の管理者許可一覧の「RLSポリシーなし」という意図したINFOに加え、既存Auth設定の[漏洩パスワード検知が無効という警告](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)があります。動画実装では認証設定を変更していません。
