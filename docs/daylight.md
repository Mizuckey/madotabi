# 日照時刻と夜景

景色ごとの「夜景ON（日没後も再生）」を保存します。追加・編集とも初期値はOFFです。既存レコードもOFFです。

- OFFは、登録した地点の日の出以上・日の入り未満だけ再生します。
- 地点未登録、取得中、通信失敗、当日の時刻がない場合もOFFは再生対象外です。
- ONは、地点や日照取得の状態にかかわらず再生対象になります。
- 日没で現在の景色が対象外になったら、登録順に次の再生可能な景色へ進みます。自動切替を停止中でも、日没を過ぎた景色は終了します。
- すべて対象外ならプレーヤーを外して休止案内を表示します。翌日の日の出に対象が戻ると再開します。チャンネルのライブ通知は休止中も利用できます。
- 他の景色が対象へ追加・除外されても、現在の景色が対象のままならプレーヤーを作り直しません。
- チャンネル通知から開くライブや単体動画ページは明示的な視聴なので、この登録景色の時刻制限は適用しません。

一覧には登録地点の日の出・日の入りを日本時間で表示します。地点は市区町村などの代表地点なので、カメラの厳密な地形・遮蔽物による明るさとは異なります。下の情報帯は引き続き全登録景色のタイトルと天気だけを流します。

## 取得と時刻処理

Open-Meteo Forecast APIの `daily=sunrise,sunset`、`forecast_days=2`、`timezone=Asia/Tokyo`、`timeformat=unixtime`を使います。Unix秒をミリ秒に変換して絶対時刻で比較するため、PCの表示タイムゾーンに依存しません。

同一座標の取得を共有し、日本時間の次の午前0時までキャッシュします。最大100地点。表示中は5分ごとにキャッシュまたは通信失敗の再取得を確認し、タブに戻った時も更新します。次の日の出・日の入り・日付境界にタイマーを予約して対象を再判定し、時計の変更にも最長1分で追従します。8秒の通信タイムアウト、当日データの検証、古い非同期応答の無視を行います。サーバーの定期ジョブ・APIキー・SDKは追加しません。

`camera_submissions.night_view`は本人の既存RLSで保存します。日照時刻は派生データなのでDBへ永続化しません。メモ欄は画面からなくしましたが、保存済みメモは削除しません。

## 検証

標準テストで日の出ちょうどの開始・日の入りちょうどの終了・翌朝の復帰・未登録や失敗時の除外・夜景ONの例外・日本時間の日付境界・取得共有と日付更新・不正なAPI応答拒否・対象外を飛ばす巡回・ドラッグの順序変換を検証します。

実際のOpen-Meteo APIから日の出・日の入りを取得し、DBでは夜景ONの本人による保存をロールバック付きSQLで確認しました。ローカルの疑似DBで、PCと390px幅のドラッグ保存、キーボードでの順序変更、夜景ONの保存を確認しました。検証専用の仮の日照応答で、再生中の動画の日没終了、日の出による対象復帰、対象のままの動画の維持を確認しました。仮の時刻・動画情報は `work/` 内だけに置き、本番には含めません。

公式仕様：[Open-Meteo Forecast API](https://open-meteo.com/en/docs)。
